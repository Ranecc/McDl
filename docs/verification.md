# 校验安装结果

下载完成不等于文件正确。这一篇讲的是装完之后复核磁盘上的 `.minecraft`：逐个比对文件的大小与 SHA1。发布包（exe、zip）的哈希与签名是另一件事，见 [verifying-releases.md](verifying-releases.md)。

实现是 `McDl.Core` 的 `InstallVerifier`，图形界面与命令行共用同一份逻辑。**校验只报告，不删除、不改写、不自动修复。**

## 校验什么

按安装计划里的每个文件复核三件事：在不在、大小对不对、SHA1 是否一致。

- 计划里没有 SHA1 的文件（部分上游不给，例如某些 Fabric 库）只比存在性与大小，不比内容。
- 按路径去重：同一个文件在计划里登记两次只查一次。
- 大小不符时不再算哈希，直接判不符；**大小相同也会算哈希**——大小相同不代表内容对。实测改掉 `1.21.4.jar` 一个字节，大小仍是 28335587 / 28335587 字节，照样报「不符」。所以不能只比大小。
- 哈希用 4 个线程流式计算，不把 40 MB 的客户端 jar 整读进内存；单个文件读不出来（杀毒软件独占、权限不足）按不符上报，不当作通过，也不中断整体校验。
- 结果按标签、路径排序，同一份计划总是给出同样的输出。

**覆盖范围以安装计划为准。** Forge / NeoForge 的 installer 会自己往 `versions\` 与 `libraries\` 里写文件，那些路径不在 `plan.Files` 里，`verify` 看不到；计划里只有 installer 本身（`<root>\.mcdl\installers\`）与下载器拉取的那部分。installer 产物的正确性由它的退出码与 `VersionId` 检查负责，见 [loaders.md](loaders.md)。

## 什么时候跑

**安装结束时自动跑一遍。** 下载阶段已经逐文件校验过 SHA1，这一遍防的是「落盘之后被改」：杀毒软件隔离、磁盘问题、别人手动替换。

**图形界面的「校验文件」按钮。** 只有解析出计划之后才可用——先点一次「开始安装」让它解析，按钮之前是灰的。适合隔一段时间复查，或者启动器报「文件损坏」之后确认是哪几个。

**命令行 `mcdl verify`**，见下一节。

## 失败时怎么处理

只报告，不删文件：

- 日志写一行告警，再逐条列出问题文件。命令行用 `不符 <标签>：<路径>` / `缺失 <标签>：<路径>`；图形界面用 `哈希不符` / `缺失`，最多列 5 条，其余写「…还有 N 个问题文件，详见本次日志」。
- 图形界面在「安装结束自动校验」与「手动点校验」两条路径上给同样的结论：文件状态栏写「有文件校验失败，文件保留未删除」，并弹一个标题为「文件校验未通过」的警告框说明这些文件没有被删除或改写。
- **安装结果仍然算成功。** `InstallSummary.Verified` 与 `Succeeded` 是分开的两件事：校验不符说明文件可能被改过，但文件确实都在盘上，下载本身没失败，不该让用户把整个安装当失败重来。
- 命令行用退出码 2，让脚本能区分「文件有问题」和「网络 / 解析错误」。

修复办法是重新跑一次安装：已经对的文件按 SHA1 跳过，只补缺失与不符的那些。实测删掉一个库、改坏一个 jar 之后：

```powershell
mcdl install 1.21.4 --root <安装目录>\verify-e2e --no-assets
```

```
done: 2 downloaded, 67 already present, 0 failed
```

再 `verify` 即全部一致、退出码 0。同一批文件反复被改，先查磁盘与杀毒软件，而不是重复点安装。

## 命令行

```
mcdl verify <version|pack.zip> --root DIR [--no-assets] [--threads N]
```

`--root` 在 `verify` 下是**必填**的。`mcdl --help` 里这一行的原文是 `root : target .minecraft directory (defaults to ./.minecraft; required by verify)`。原因很实际：默认的 `./.minecraft` 常常是空目录，校验出来「全部缺失」没有意义，还会让人以为装坏了。缺 `--root` 或缺目标时打印 usage 并返回 1。

它和 `plan` 一样只解析、不下载，然后逐个复核磁盘。目标可以是版本号，也可以是已存在的整合包文件（按整合包解析）。干净时：

```powershell
mcdl verify 1.21.4 --root <安装目录>\verify-e2e
```

```
resolving 1.21.4 ... 1.21.4 (1.21.4), 69 files
root: <安装目录>\verify-e2e
verifying ...
校验 69 个文件：全部一致
```

改坏一个 jar、删掉一个库之后：

```
verifying ...
校验 69 个文件：缺失 1 个，哈希不符 1 个
  不符 1.21.4.jar：...\versions\1.21.4\1.21.4.jar（大小 28335587 / 28335587 字节）
  缺失 jackson-annotations-2.13.4.jar：...\libraries\com\fasterxml\jackson\core\jackson-annotations\2.13.4\jackson-annotations-2.13.4.jar
```

「不符」后面括号里是实际 / 期望字节数，两个数相等就是「大小对、内容不对」。

退出码：

| 码 | 含义 |
| --- | --- |
| 0 | 全部文件一致 |
| 2 | 有文件缺失或哈希不符 |
| 1 | 用法错误（缺 `--root` 或目标）、解析失败、网络错误 |

**2 不是 `verify` 独占的。** 任意命令被 Ctrl+C 取消时命令行也返回 2，stderr 是 `cancelled`。脚本里要区分，就再看 stderr 有没有这一行，或者只在 `verify` 的上下文里把 2 解释成「文件有问题」。

`--threads` 只影响解析阶段；校验本身固定 4 个线程。

## 它不能替代签名

两件事解决的是不同问题，不能互相顶替：

| 手段 | 能说明 | 不能说明 |
| --- | --- | --- |
| 装完的校验（这一篇） | 磁盘上的文件与本次解析出的官方清单（大小、SHA1）一致 | 下载器本身是否可信、这份清单来自哪一次元数据 |
| 发布包验签 + 哈希（[verifying-releases.md](verifying-releases.md)） | 手上的 exe / zip 来自本仓库的发布流程，字节没被换 | 装完之后 `.minecraft` 里的文件有没有被改 |

装完的校验不证明 exe 干净：一个被改过的下载器完全可以先下载正确的文件再干别的，或者干脆按自己的清单校验。反过来，验签证明的是发布产物本身，管不到运行之后的磁盘。

还有一层是它天然做不到的：**校验不能证明「这是正版游戏」**。它比对的是公开可下载的文件，与账号无关；需要身份的是「进服务器玩」那一步，由启动器与服务端（online-mode）负责。本项目不接登录的理由见 README 的「为什么不登录、不做正版校验」。
